# ExiEngine security model

## Threat boundary

The engine treats game assets, atlas JSON, save data and pointer/keyboard input as an untrusted boundary. Game code, on the other hand, runs in the application owner's same JavaScript realm; ExiEngine does not promise to sandbox it.

## Defaults

1. Asset URLs are limited to the same origin as the base/origin snapshot taken in the constructor. A different origin can only be added with an explicit `allowedOrigins` choice; mutation of the public `baseURL` or the allowlist is rejected before it reaches the resolver.
2. Asset response byte counts, image sizes and atlas frame counts are limited.
3. The renderer enforces a total GPU texture byte/count budget; atlas subtextures count as a single `baseTexture` resource.
4. Redirects, data URLs and unsupported protocols are rejected.
4. Shader and WGSL text is never built from asset, network or AI-agent data. The only extension point is `registerFilter()`, a local game-code API that inserts bounded function bodies (see "Custom filters" below); the MCP bridge and the browser RuntimeAgent cannot see or call it.
5. Save data is stored only as JSON; the namespace is limited to 64 characters, key names to 128 characters, and values by byte size. `maxBytes` is tied to an absolute 16 MiB ceiling; set/get JSON depth is limited to 64 and a rough node/token budget of 100,000 before `JSON.parse()`, and directly raising the public `maxBytes` is rejected.
6. Pointer capture/cancel, visibility and `pagehide` transitions clear stuck keyboard/pointer/gamepad state.
7. Input action names, binding counts, raw keyboard state and keyboard/gamepad indexes are bounded; action bindings remain data and run no callbacks/eval/scripts. Gamepad hot-plug callbacks only receive the engine's snapshot with the 128-character ID, 32-axis and 64-button limits applied. `Input.destroy()` is idempotent, and native callbacks that arrive late after teardown cannot recreate the input state maps.
8. Gamepad indexes are limited to 0..15, IDs to 128 characters, axis counts to 32 and button counts to 64; axis values are clamped to `[-1, 1]`, snapshot arrays are reused within this capacity, and a disconnect safely releases pressed buttons within one frame.
8a. Input axis names and the total action/axis binding collection are limited to 256, and binding counts to 8. `deadzone` is clamped to 0..0.99, `scale` to -1..1 and the result to -1..1; analog input cannot create unbounded arithmetic or collection growth. Even if the public runtime Maps are changed directly, `getAxis()`/action queries and snapshot paths re-validate this capacity.
8b. Raw keyboard state is limited to 256 keys; codes longer than 64 characters or empty, and unknown keyup events, are not written to the Sets.
8c. `Input.setBindings()` validates action/axis names, binding types, the 8-binding-per-map limit and the 256 total-entry limit with the existing normalize functions; on a conflict or invalid entry the maps are not changed (atomic). `getBindings()` only returns a deep copy; changing the snapshot cannot change the live input state.
8d. `Input.rumbleGamepad()` only accesses gamepad indexes 0..15; duration is limited to 10 seconds and strong/weak magnitude to 0..1. Without a native `dual-rumble` or legacy `pulse` actuator it returns `false`, a haptic exception does not break the game input flow, and the native Gamepad object does not leak into the snapshot API. The `beginFrame()`/`endFrame()`/pointer snapshot paths also reject public state Map/Set overflow before consuming them.
9. Pointer handlers are only callbacks explicitly provided by game code; asset data cannot register handlers. The primary pointer-down target is captured through a scene hit-test, up/cancel are sent to the same target, and move/enter/leave only go to visible hit-test targets. Down/up/move/cancel/wheel events bubble up the parent chain as deep as the current scene graph; `pointerenter`/`pointerleave` do not. The event object is reused as a transient; `stopPropagation()` only stops the current dispatch and runs no user callback or asset code.
10. The demo server binds to loopback; it only serves the allowlisted web extensions needed by the engine/game, hides hidden/dot files and dependency lock metadata with `404`, and returns `400` if the resolved path of a traversal lies outside the workspace.
11. The server smoke in `npm test` verifies CSP, `nosniff`, CORP, referrer/cache headers, `HEAD`/method behavior, 404 and encoded path traversal rejection with real HTTP requests.
12. `npm run verify` reruns the static security scan, the HTTP smoke, the engine smoke and all allocation/streaming benchmarks in a single release gate; browser/device evidence is required separately.
13. During bulk reparenting, `Node.add()` first runs all node type, cycle and duplicate checks; a validation error leaves no partial scene graph mutation.
14. `tools/exi-mcp-server.mjs` only exposes the fixed `src/index.js` export surface; MCP JSON-RPC messages are limited to 1 MiB, strings to 64 KiB, tool outputs to 64 KiB (256 KiB for the engine-generated `exi_api` manifest, which carries no caller or project data), binary arguments to 512 KiB, JSON values by depth/fields/items, the scene graph to 1,024 nodes/depth 32, batches to 128 calls and the handle table to 4,096 entries. The bridge supports dual eras: the MCP `2026-07-28` modern `server/discover`/per-request `_meta` era and the legacy `initialize` era; the protocol version and the required `clientCapabilities` in modern metadata are validated, and an unsupported version is rejected with `-32022` listing the supported versions. `tools/call` requests are processed in a single queue to prevent session state races; batch references only reach earlier same-batch results (`$result`), nested batches are rejected and no transaction/rollback is promised. A long-running active or queued tool is cancelled without producing a response by a `notifications/cancelled` notification carrying the same request id; the syntax-check child processes of `exi_check`, `exi_project_check` and `exi_project_open` are terminated in bounded form. Handle calls are limited to the engine prototype chain with the public names in the class-based allowlist in `src/ai/public-methods.js`, and static calls only to class own-property descriptors; internal renderer/cache/validation helpers (such as `assert*`, `build*`, `getRenderItems`) are not visible on the MCP and browser RuntimeAgent surface. There is no `Object.prototype`, `Function.prototype`, `__proto__`, `prototype`, `constructor`, `_private`, callback, eval, dynamic import or arbitrary shell.
14a. `findGridPath()` validates external input as a rectangular grid; the grid is limited to `MAX_GRID_PATH_CELLS` cells, `blockedValues` to 32 values and `maxNodes` to the cell count. A* only runs on a bounded typed array/heap, does not modify the grid, runs no callbacks or scripts and returns in a controlled way with `truncated:true` at the limit. This prevents large or malformed navigation data from MCP from turning into unbounded CPU/memory work.
14b. MCP result/inspect/session-status and browser `RuntimeAgent` serialization use prototype data descriptors for the object type and destroyable metadata; they do not run `constructor` or `destroy` accessors through normal property access. Value getters are only evaluated when `exi_get`, `exi_export_get` or the related public call is explicitly requested.
15. MCP `exi_scaffold` can only write relative files under `EXI_MCP_ROOT`/the repo root, rejects engine/test/tool roots, traversal/absolute paths and symlinks, first stages all starter files to unique temporary files, and if a multi-file commit is interrupted it tries to remove the new files and restore the backups; it does not overwrite existing files without `overwrite=true`. `exi_project_open` runs an existing folder through the same root, symlink and engine/test/tool checks; it statically checks checkable HTML/JS/JSON files without running code, does not take a project without such a file into the session scope, and drops the scope record if the check fails. `exi_file_list`/`exi_file_read`/`exi_file_write` only access project folders scaffolded or opened with `exi_project_open` in the same session, allowlisted text extensions and non-symlink paths; single-call text writes are limited to 64 KiB, chunked text files to 4 MiB, chunks to 48 KiB, the pending total to 16 MiB and active transfers to 8. Large reads are split into 48 KiB pages that preserve UTF-8 boundaries. Listing is limited to 1,024 files/32 folder levels, missing parent folders are only created inside the project scope, and `.env`/credential and binary files are rejected. Direct and chunk overwrite writes first go to a unique temporary file; the old file is moved to a special backup name, and if renaming the new file fails the old file is restored, so a failed write does not delete the existing source. `exi_file_check` only statically checks `.html`/`.js`/`.mjs`/`.json` within the same scope; it limits HTML external/executable URL and traversal references, JS with a fixed Node `--check`, and JSON with a pre-parse 16,384-node/32-depth budget followed by `JSON.parse()`; it runs no code and opens no shell. As a result, `package.json`, engine sources or test/tool code cannot be changed with the file tools. MCP notifications are consumed without producing a response; MCP shutdown signals clean up started preview child processes. `exi_check` only runs `doctor`, `test` and `verify` from the fixed npm scripts; the bridge's stdout contains only JSON-RPC responses.
16. MCP resources only return the fixed API/type/guide/security/runtime/clients contracts; no arbitrary file read is possible through a resource URI. `prompts/get` only produces bounded text messages; a prompt argument grants no tool, shell or file-write permission. `exi://runtime` is a selector/attribute and telemetry endpoint contract; browser state is only carried to the MCP process through the whitelisted report the scaffold page sends to the same loopback preview process. A crypto-random token is generated for each preview, the token is only accepted in the `x-exi-runtime-token` header, the body is limited to 4 KiB and field values are bounded/whitelisted; the token is not returned in the MCP `exi_preview_start` result. The token endpoint and telemetry route are only active in loopback previews started with `EXI_RUNTIME_TOKEN`. `exi://clients` only returns command/config text and does not change client config files. `exi_export_get`/`exi_export_call` only open own-property paths of the `src/index.js` export tree; there is no prototype traversal. Static singletons (`Texture.white`) are not destroyed, as protected handles. `exi_preview_start` only starts the repo's `server.mjs` process on loopback `127.0.0.1`; the optional `path` is first decoded and reduced to a safe preview path with absolute/traversal/backslash rejection, `ready` is not returned until the target page answers HTTP 200, and `pageUrl` is only built from this safe path. The preview probe enforces GET, redirect and 64 KiB response limits, and stops the child process when the session closes. Synthetic telemetry written by MCP is not accepted as real browser/GPU evidence.
16a. `exi_preview_call`/`exi_preview_batch` only use the `/__exi/runtime-command` and `/__exi/runtime-result` endpoints of the same preview started with a crypto-random token. The command payload is limited to 768 KiB, the result to 64 KiB, the queue to 64 commands, a batch to 8 operations and the wait to 10 seconds; timeout/cancellation tries to delete the pending command. The demo and scaffold `RuntimeAgent` only use the `src/index.js` exports, the `engine`/`scene` root handles and the class-based public method allowlist in `public-methods.js`; root handles cannot be released. `observe` only calls the engine's own temporary RenderTexture readback bounded to 64×64 or an explicitly configured canvas observer; `snapshot` only extracts a scene graph of at most 64 nodes/page, 4,096 visits and depth 32 from direct data descriptors. Neither operation takes a raw screenshot or accesses arbitrary DOM/global/window, getters, callbacks or scripts. There is no `eval`, `new Function`, dynamic import or callback serialization. Browser handles are separate from MCP process handles; without a RuntimeAgent, a synthetic HTTP acceptance does not count as GPU evidence.
16b. Through the browser RuntimeAgent, `Input.inject*` only reaches the engine's public Input instance methods; it runs no native DOM/OS input, arbitrary event target or callback source. The core limits a single tape to 128 events, key/pointer texts to 64 characters, coordinates to ±10,000,000, pointerId to 31 bits and button to -1..30. For deterministic replay, use the `engine.stop()` + bounded `Input.inject()` + `engine.step()` order; `inject` does not roll back engine state and promises no transaction/rollback.
16c. The `scenario` operation is not a generic method chain: it only uses the `stop()`/`step()`/`start()` prototype methods of the protected engine root, the `input`/`scene` roots taken from direct data descriptors, the `Input.inject()` method and the preconfigured observe/snapshot helpers. A scenario is limited to 16 frames, 512 total events, 128 events per frame, 1,024 observe cells and 16 snapshot nodes/page; `resume` only restarts an engine that was running before the test. There is no rollback on error, and completed frames are not undone.
17. The `.codex/config.toml`, `.mcp.json`, `.gemini/settings.json`, `opencode.json`, `.cursor/mcp.json` and `.cline/mcp.json` files in the repository only define the local MCP stdio bridge command; they contain no secrets and connect to no external service. A config added manually at user level for Windsurf/Cascade must use the same local command. Because clients can enable these project settings automatically, teams should review the files and only enable them in working roots they trust. `npm run test:clients` verifies that the six repo files only use the expected `node tools/exi-mcp-server.mjs` command.
18. `exi_asset_list`/`exi_asset_read`/`exi_asset_write` are a binary boundary separate from the text file tools: they only list allowlisted image/audio/font/KTX2 extensions with metadata in project scopes scaffolded or opened with `exi_project_open` in the same session, return a byte range of up to 32 KiB without loading the file into memory, or write with a 512 KiB `$bytes` payload. `.env`, credential/executable extensions, traversal and symlinks are rejected; an existing asset is not overwritten without permission. This payload is a trusted MCP client boundary and does not replace the asset decoder's security checks.
19. Chunked asset upload preserves the same allowlist; temporary files are inside the scaffolded or opened project scope, offset order is mandatory, and limits are 64 MiB per asset, 64 MiB pending in total and 8 active transfers. Uncommitted temp files are cleaned up on `exi_asset_abort`, `exi_session_reset` or process shutdown; before commit, the symlink/file type of the target file is checked again.
20. `exi_project_check` only scans allowlisted text files in the project scope scaffolded or opened with `exi_project_open`; it is limited to 128 checkable files/32 error summaries. It uses a fixed Node `--check` for JS/MJS, a pre-parse budget for JSON and a local reference check for HTML; it runs no arbitrary script, shell or browser code.
20b. `exi_project_status` only collects the existing bounded file/asset metadata, the `exi_project_check` result and the `/__exi/runtime` GET report of the MCP preview children belonging to this scope for the same scaffold/open scope. It runs no new process, script or browser command; without a runtime report it returns `telemetry:null`/`runtime.ok=false`. The directory match is assigned session-locally when the preview starts; previews of other projects do not leak.
20c. `exi_session_status` only returns bounded descriptor metadata of the session maps: handle id/type/protected/destroyable, relative project scope, upload target and byte progress, preview id/page URL/port/readiness. No handle getters, runtime tokens, temp paths or file contents are exposed, and no new process, script or browser command runs; after `exi_session_reset` the maps are emptied.
20d. On a direct `exi_preview_start({ path })` call, the project match is only made from the parent of the decoded safe path inside a session-local scaffold/open scope; out-of-scope or root previews stay `directory:null` and do not leak into other projects' status results.
20a. `exi_project_preview` first runs `exi_project_check` in the same project scope; if the check fails it starts no child preview and returns `preview:null`. After a successful check it only passes the safe `${project}/index.html` path to `exi_preview_start`; the preview child is still subject to the loopback, target HTTP-200 readiness, token and cleanup limits. This combined tool is a static check/HTTP readiness convenience; it does not run a browser or GPU.

## Deliberately not done

The MCP bridge and the browser `RuntimeAgent` limit the inline byte payload of typed-array/`DataView` outputs with `maxInlineBinaryBytes=32 KiB`; larger values only carry `truncated` metadata. This limit is in addition to the general tool/runtime result limits and does not raise the 512 KiB limit of binary input. BigInt typed-array sample values are converted to strings to prevent JSON serialization errors.

- Script, WASM or executable content inside assets is never run.
- There is no HTML template or arbitrary JavaScript engine API. User shader code is limited to `registerFilter()` function bodies registered by the game's own code (not reachable by agents).
- The audio and image loaders do not extend remote-origin trust on their own.
- Production authentication, CDN signature verification and service-worker isolation are not the engine's job; they must be done in the distribution layer.
- MCP client authentication, user/agent authorization and process isolation are not the engine's job; only connect the bridge to a trusted local agent and constrain it separately with OS/container permissions in production.

## Text cache safety

`ParticleEmitter.maxParticles` is limited to an absolute 100,000 entries; emit/update/render/instance inputs validate the created typed-array capacity and public `particles`/`maxParticles` mutation in O(1), and uncontrolled typed-array or CPU render work is rejected.

Particle rate, lifetime, size, coordinates, velocity, acceleration and delta values are kept in a bounded finite range; an invalid random callback falls back to the default random source, and an `Infinity` simulation step does not corrupt state. Dead particle records are reused in an object pool that does not exceed the `maxParticles` limit; input-driven churn does not turn into unbounded object growth.

The engine viewport size is limited to 16,384 pixels even after CSS/DPR resizes, `fixedStep` to 1 second and the frame delta to 5 seconds; infinite/NaN configuration values fall back to safe defaults.
The public `width`/`height`/`resizeMode`, `maxPixelRatio`, texture budget, `fixedStep` and `maxFrameDelta` fields of the `ExiEngine` runtime configuration are tied to the constructor snapshot; the official `setLogicalSize()`/`setResizeMode()` paths update the snapshot, and direct mutation is rejected at runtime inputs with `EXI_ENGINE_CONFIG`. During fallback, the new renderer inherits the same budgets.
The physical canvas resolution and the world viewport are separate: `Camera.pixelRatio` is limited to 0.25..4 and also applied to the WebGPU GPU-culling uniforms; a high DPI value does not unexpectedly enlarge the world area.

`backgroundColor` is only normalized to a finite 24-bit color value or a validated `#rgb`/`#rrggbb` form; `backgroundAlpha` is clamped to 0..1. `clearBeforeRender: false` requires the application to deliberately rely on the previous canvas content and does not change the default clearing behavior.

`Camera.follow()` processes target and offset coordinates as finite values; invalid targets are rejected, and an invalid follow coordinate does not carry `NaN`/`Infinity` into the camera.

`Camera.shake()` limits amplitude to 2,048, duration to 10 seconds and frequency to 120 Hz; invalid values cancel the shake. Each frame the previous offset is undone, the new offset is written with bounded world values, and `clearShake()` clears without leaving the active offset behind.

`Camera.setBounds()` only accepts a finite, positive rectangle; the clamp calculation accounts for the zoom and rotation visible area and safely pins the center for very small worlds.

The number of fixed-step updates in a single render frame is limited to 240; a backlog accumulated after a background tab or a long stall cannot grow large enough to lock the browser.

`pauseOnHidden` is on by default: a hidden document stops the engine's RAF chain and accumulator, and continues with a new time base when visibility returns. If background simulation is deliberately wanted, `pauseOnHidden: false` can be chosen.

`timeScale` is kept finite in the 0..16 range; even if a corrupted value is written directly, it is normalized at every simulation step, and the scaled delta cannot exceed the `maxFrameDelta` ceiling. This prevents the fast-forward option from exceeding the fixed-step catch-up limits and locking the CPU.

`interpolate` only produces temporary transform values with a finite `0..1` render alpha; at the end of every path, including a render exception, node transforms are restored to the current game state. Interpolation snapshots run no asset or user code and are off by default.

`AssetLoader` enforces absolute ceilings of 16,384 px image size, a 16 MiB texture pixel budget and a 64 MiB response byte budget; it checks known PNG/JPEG/WebP/GIF/BMP header sizes before `createImageBitmap()`/`Image.decode()` and re-validates the measurement after decoding. Constructor options cannot raise these limits. The `TextureAtlas` JSON/grid/pack paths also validate frame, size and pixel budgets against absolute upper limits; these checks cannot be bypassed with options such as `Infinity`.

`TextureAtlas.pack()` validates the size/crop coordinates of CanvasImageSource, `Texture` and atlas subtexture sources; the padding total goes through a safe-integer/atlas-size check, and large safe-integer inputs are kept out of the packing arithmetic.

`AnimatedSprite` snapshots constructor/setFrames inputs; it limits the frame count, the frame rate and a single update step. `gotoFrame()`/`update()` re-validate the frame limit even if the public `frames` array is overflowed directly; no infinite frame loop or `Infinity` time input can occur.

`Tween` keeps target/value/duration/delta inputs in a finite range; it rejects easing and completion callbacks that are not functions.

`Animator` is limited to 4,096 active tweens by default and 65,536 absolute. `add()` and `update()` re-validate the created capacity, public `tweens` Set overflow and direct `maxTweens` mutation in O(1). Adding the same tween again consumes no capacity; `remove()` and the cleanup of completed tweens give the slot back. This limits game callbacks from growing CPU/heap by adding tweens without control.

`ExiEngine({ animator })` only calls an explicitly provided animator that has an `update()` function, once per fixed step; animator callbacks run inside the engine's runtime-error boundary. If an animator and physics are both provided, the order is deterministically scene update, animator update, physics step and `onUpdate`.

The `CollisionWorld` spatial broadphase option sets absolute limits on colliders per cell and query cell counts; overly large collider/query areas fall back to a safe full scan. The local `bounds` override of `Collider`/`PhysicsBody` is finite, positive and capped at 1,000,000 world units; `oneWay` only accepts the four validated direction values and takes a static/kinematic collider out of the solid solver if the movement direction/starting side does not fit. A collider bound to a destroyed Node cannot be added to the world and does not leak into query output; a destroyed PhysicsBody is removed from the world at the next physics step. When bounds change, the spatial index becomes dirty and is safely refreshed at the next query. `raycast()` keeps the direction, distance and broadphase area finite and within 1,000,000 world units. The explicit `syncCollider()`/`rebuild()` contract for generic moving colliders is kept; for its own dynamic and kinematic body movement, `PhysicsWorld` only updates the cells of the related collider incrementally, limits velocity with `maxSpeed` and keeps the grounded carry delta within the world-unit ceiling. Kinematic bodies receive no gravity/rigid-body impulse; fast bodies cannot pass through thin static/kinematic colliders.

`CollisionWorld({ autoSync: true })` only eases this explicit rebuild rule for opt-in use; it does a stale-transform check proportional to the collider count per query. This cost is not added to the default fast path.

`PhysicsWorld` limits the body count to 10,000; the `step()`, `overlaps()` and spatial sync inputs re-validate this budget in O(1) even if the public `bodies` Set is overflowed directly. It keeps overlap output in the caller-provided/reused list, delta to 0.25 seconds, the fixed substep count to 16, and gravity/velocity/position arithmetic finite and within 100,000 world units; the physics solver produces no uncontrolled typed arrays or recursive graphs.
`PhysicsWorld({ autoSync: true })` checks static/dynamic collider AABBs against geometry values as well as the transform version; when a sprite size or drawing/tile content changes, no stale broadphase is used. The O(n) pre-query check needed for this accuracy is off on the default fast path.

`SpriteBatch` spatial culling also sets an absolute limit on cells per sprite; cells are kept in a nested numeric `Map` with no string key generation, overly wide sprites go through the visibility check in a bounded fallback list, and no uncontrolled cells are created.

`Node.cullBounds` only uses an explicitly given finite local rectangle for subtree coarse culling; a branch outside the bounds is cut before it enters the render queue, and bounds validation produces no unbounded metadata in the scene graph.

`Node.add()` rejects destroyed/cycle-creating nodes and more than 65,536 children per parent. For direct public `children` mutation, the update, interpolation, layout, world-matrix, render/hit-test and destroy traversals detect duplicates/cycles with a per-traversal stamp; graph depth is limited to 1,024. `destroy()`ed Nodes cannot be re-added to the scene graph and run no update callback; the engine's scene/overlay transitions reject destroyed graphs. This prevents a graph whose GPU/asset lifecycle has ended from leaking back into the new frame flow.

Renderer context/device loss errors are marked with backend and phase/reason information; WebGPU loss and WebGL context-restore failure are separated as `recoverable: false`. The engine's `onStatus` observer is outside the trust boundary: an observer exception cannot interrupt the loss, fallback, restore or teardown flow.

Node alpha values are normalized to `[0, 1]`; parent alpha is multiplied into children as `worldAlpha` and included in the regular/static/instanced render cache keys. Zero alpha is filtered from the render queue; user input cannot produce unbounded color or GPU stream values.

Node filters only reach the built-in shader branches (`FILTER_TYPES`) and filters registered with `registerFilter()`; the filter amount is normalized to `[0, 1]`. The WebGPU filter uniform buffer is reused according to the batch count and limited to 16 MiB; user input cannot create dynamic shaders or unbounded GPU allocations.

`Node.clipRect`, `maskRect`, `cullBounds` and `hitArea` are validated as finite, positive rectangles bounded by `MAX_WORLD_COORDINATE` at the world update boundary as well as in the constructor/setters; direct public field mutation is normalized without allocation or rejected. `maskTexture` is validated as a real `Texture`/`RenderTexture` instance at the constructor/setter and world update boundary; inherited mask texture/rect arguments go through the same check. It is only sampled through the existing bind path, creates no mask buffer or recursive pass allocation, and a source/target feedback loop on the same RenderTexture is rejected in both backends.

TileMap CPU culling only scans a bounded row/column range of the camera's local AABB; the range is clamped to the map dimensions. `cullTiles: false` only changes a performance preference and cannot exceed the tile allocation limit. The `instanced: false` regular render path reuses the item/positions/UV pool within the bounded tile count.

The `TileMap.setRegion()` region size is clamped to the map bounds and the existing tile limit; no cell is written until all tile indexes are validated.
`TileMap.getCollisionRects()` works on a grid with a bounded tile count; it only produces adjacent solid cells as merged rects. `createStaticBodies()` validates the new body/node list during rebuild, cleans up new pieces on a PhysicsWorld add error and restores the previous bodies.

The total `SpriteBatch` sprite count is also limited to 100,000; the CPU quad, instanced stream, bounds and spatial-culling inputs validate the same limit in O(1) before rendering even if the public `sprites` array is changed directly, so it cannot allocate uncontrolled JavaScript/GPU memory.
`SpriteBatch` animation accepts at most 4,096 frames, 240 FPS and 4,096 frame steps in a single update; frame lists are limited to the same atlas/base texture. When a frame changes, `addAnimatedSprite()` only invalidates the existing batch cache and creates no new scene node or GPU buffer for each animation frame.
`SpriteBatch.addSprites()` first normalizes all entries and validates the texture/sprite limits; on an error the batch is not partially written, and a successful bulk add makes only one cache invalidation.
`SpriteBatch.markDirty()` explicitly requests a cache/spatial index refresh for directly changed sprite records; the core does not add unpredictable O(n) cost by scanning public records every frame. `setSprite()` uses the normalized safe path.
The `SpriteBatch` spatial visibility query converts the camera corners into a bounded local cell range; if the safe integer/range validation fails, the existing full-scan fallback is used, so corrupted transform input does not turn into unbounded Map traversal.

The pointer cancel, blur, visibility and pagehide paths release active pointer captures; valid pointer IDs are normalized to safe integers and at most 32 pointer states are kept at once. Interactive capture/hover targets are kept per pointer ID, the hover record is cleared on touch release or when input state drops at the end of a frame, `onWheel` only goes to the game callback selected by a scene hit-test, and at the end of the frame the convenience pointer ID is synchronized with the active pointer state.

Camera viewport/zoom/bounds, Node transform, Node `hitArea` and Sprite geometry inputs convert non-finite numbers to safe defaults or reject them; `Camera.bounds` is re-validated at the `clampToBounds()` boundary after direct public field mutation. `MAX_WORLD_COORDINATE` (1,000,000,000) also puts an upper limit on finite but extremely large world values. `Mat3` multiplication/transform intermediates and Graphics primitive vertices are kept bounded before overflow; `NaN`/`Infinity` are not carried into the GPU vertex stream.

Graphics geometry commands are normalized to finite numbers and the total command count is limited to 4,096; the render and bounds inputs re-validate this limit in O(1) even if the public `commands` array is changed directly, and an invalid or unbounded primitive stream is rejected in a controlled way. The dirty rebuild path reuses the same render-item/positions/bounds memory; when the command count drops, old records are removed from the render list.

The `Graphics.polygon()` point list is kept at an even length, at least three points and at most 256 points; coordinates are normalized to the world limit, ear-clipping triangulation is done as bounded CPU work when the command is added, and an invalid/untriangulatable shape is rejected. A render frame runs no new triangulation.

`ParticleEmitter({ gpuCulling: true })` only produces 16-float GPU source records up to the created capacity; WebGPU compute culling produces the screen-space compact output. WebGL2 processes the same emitter with the CPU instanced fallback; if the public particle array is overflowed directly, both paths fail in a controlled way.

`RenderTexture` width/height values are limited to integer 16,384 px and a total 16 MiB pixel budget; a WebGL2 framebuffer is not taken into the target cache until its completeness is validated, and the WebGPU target texture is created with render-attachment, sampling and, when needed, `COPY_SRC` usage flags. `captureFrame()` also limits the grid to 64×64 and 4,096 cells, destroys the temporary target at the end of each call and returns at most 16 KiB of packed RGBA8 pixels; the RuntimeAgent serializer separately limits this output with the 32 KiB inline binary and 64 KiB result limits. The `observe` operation reduces this low-resolution data to a text grid and returns no raw bytes. During a resize, the old framebuffer/texture is not deleted until the new target resources have been successfully created and validated; an allocation error does not break the current working target. `renderToTexture()` rejects a camera viewport mismatch and stops sampling the same target within the same pass as a feedback loop; a target that does not fit the device's narrower texture limit is a user input error and is not handled as device loss.

Renderer texture inputs also validate the lifecycle: a destroyed normal texture, atlas frame or base texture cannot access the GPU cache or allocate a placeholder again, and is rejected with a controlled TypeError with code `EXI_TEXTURE_INPUT`. Atlas frames read the same base filter state; a filter change on one frame stays consistent across sibling frames and the shared GPU residency of both backends. If the atlas's external base texture is destroyed, the atlas closes lazily on its first `get()`/`getFrames()`/`has()` access and destroys its cached frames; the atlas does not take ownership of the external texture. Because the same entries in the batch queue are filtered before drawing, this check also covers direct renderer calls.

`RenderGroup` only uses existing bounded `RenderTexture` targets; each visible group is drawn in an offscreen pass in post-order, then sampled as a single quad in the main pass. If a group target appears as the color target or mask texture of the same pass, the feedback loop is rejected. A group's `destroy()` call only releases the target it owns; the lifecycle of an externally provided target stays with the user. Group children do not leak directly into the main pass; the offscreen root flag carries this boundary explicitly between the renderer and the queue.

`RenderGroup.effects` accepts at most four allowlisted filters (`grayscale`, `invert`, `brightness`, `sepia`, `contrast`, `saturate`). The ping-pong chain creates no more than two intermediate targets; if the total of the intermediate targets exceeds the 16 MiB pixel budget per group, effect setup is rejected with a controlled `RangeError`. Intermediate targets are owned by the group and released during `destroy()`; effect passes create no route when source and target are the same, so they produce no feedback loop.

`engine.prepare()` prepares group child queues and all group/intermediate RenderTexture binds only through validated existing targets; preparation also creates no new unbounded targets or shader types. Invisible groups are not taken into the preparation list because of the scene traversal visibility boundary.

Vertex/instance/texture/GPU-culling limit violations caused by a `RangeError` during WebGPU rendering also surface as `EXI_RENDER_INPUT`; these validation errors do not release GPU resources wholesale and declare the device lost. Real queue/command/device errors stay on the separate device-loss path.

An error in the middle of a WebGL2/WebGPU backend `init()` directly triggers renderer teardown; buffer, listener and device references are not kept as a half setup. WebGL2 regular/instance/static buffer capacity changes do not delete the old one until the new handle and upload complete successfully; on an error the new handle is cleaned up and the working buffer is rebound. Teardown also completes with method-level safe calls on hosts missing event APIs, such as workers/SSR.

During a WebGPU-to-WebGL2 fallback, the old lost renderer is released before the new backend is set up. If the new backend also fails to start, the engine does not keep the old GPU device/context reference alive and `renderer` stays empty; the next error goes to a controlled `renderer-error` status.

Texture sizes are limited to 16,384 pixels and UV values to `[0, 1]`; `subTexture()` validates frame coordinates within the source texture bounds.

Placeholder textures without a source use a 1×1 white allocation in WebGL2 and WebGPU; a large logical size in the metadata is not translated directly into GPU pixel memory.

The real width/height values of directly provided Canvas/Image sources are also matched against the metadata within the same limit; if the source is resized later, the `markDirty()` and renderer upload paths reject it.

The WebGL2 and WebGPU regular/static vertex buffer paths reject anything that exceeds the 64 MiB global budget and the WebGPU device limit; the static buffer path also respects the device's `maxBufferSize`.

On scene shrinking or transitions, the render batch pool releases the static owner, texture, mask and GPU resource references of unused batches; because only a bounded reuse window is kept, old scene objects are not held through the pool without limit.

The WebGL2 `MAX_TEXTURE_SIZE` security limit is read and cached during context setup and restore; the per-frame profiler query does not go to the driver again and again. On a context change, the cache is refreshed with the new context limit.

WebGL2 shader/program, vertex buffer, lazy instance/static buffer and texture creation are atomic; on a compile/link/upload or handle creation error, partially created GPU resources are deleted, the old working buffer is kept, and nothing is written to the texture cache. WebGPU `buildResources()`, the filter uniform buffer, the first static buffer upload and the GPU-culling input/output/counter/indirect/params/bind-group chain do not commit new resources on a validation/creation/upload error, keep the old working resources and clean up partially created buffers. During a context restore, the old resource tables are cleared only after the new resources have been set up successfully.

Text resources are limited by character, font definition, parsed line-height, canvas size, pixel and cache total limits. `TextCache` entry/pixel budgets are tied to the constructor snapshot; public limit mutation is rejected with `EXI_TEXT_CONFIG`. `TextCache.clear()` does not destroy active references; it only cleans up texture records that are no longer used.

`GlyphAtlas` uses fixed atlas size, maximum pixel, entry and grapheme cluster limits; the size, padding and entry/pixel budgets cannot move outside the constructor snapshot. When the atlas fills up, text drawing safely falls back to the normal Canvas path; scripts that need complex text shaping use the same fallback.

Audio resources are limited by both a compressed byte budget and a total post-decode PCM byte budget for all loaded buffers; only a complete, parsed ArrayBuffer is given to the decoder.

Audio bus names are limited to 64 characters, audio keys to 256 characters and the total bus count to 64; malicious game data cannot create unbounded Web Audio nodes or Map keys.

If an audio decode completion or a WebGPU backend start runs past engine teardown, the generation/destroy checks do not write the late result into the destroyed runtime.

Physics `Collider.layer` and `Collider.mask` values only accept safe integers in the 0..0xffffffff range. `PhysicsWorld` runs a two-way bitmask check before the solver and `overlaps()` produce output; non-matching bodies cannot enter the contact/resolution path even if they are a broadphase result.

`PhysicsWorld.overlaps()` clears the output array the caller will reuse; if the engine's internal collider scratch array is passed as the output it is rejected, so iteration that grows on the same list cannot lock the CPU.

`PhysicsWorld` contact events are only tracked if an `onBeginContact`, `onStayContact` or `onEndContact` callback is explicitly provided. Each body pair is reported once for begin/end and at every fixed step it is active for stay; during `remove()` and `clear()`, an `end` cleanup notification is made for active pairs. Layer/mask and enabled checks are kept, and without callbacks no extra contact Map/overlap scan is done. The third callback argument is only reused, transient `PhysicsContact` metadata; normal/penetration values must be read during the callback, and it runs no user data or GPU resources. Callbacks run inside the engine's fixed-step error boundary; an exception goes to the normal runtime-error flow.

`ExiEngine({ physics })` only works on an explicitly provided world that has a `step()` function; it is called once per fixed step with the bounded `fixedStep` value. `physics: null` is the default. If the world's scene is empty, it is bound to the engine scene; if a different scene is explicitly provided, automatic ownership is not taken over, and an engine scene transition does not change that external scene.

If a game callback (`Node.onUpdate`, engine `onUpdate`/`onRender` or a pointer handler) throws, the RAF chain does not look as if it stayed open: the engine stops, a `runtime-error` status is published and input frame cleanup still runs through `finally`. Node callbacks are only functions provided by the application; asset data cannot register callbacks. A manual `step()` call does not hide the error.

`ExiEngine.setScene()` does not change the current state until it has validated the new scene/camera contract; on a successful transition it invalidates the prepared render queue, clears the old pointer capture/hover Map entries and realigns the canvas/camera viewport. The old scene is not destroyed automatically; ownership stays with the application.

`ExiEngine.setOverlay()` only accepts validated Scene/Camera-like objects. The overlay pass is drawn over the main canvas with `load`, without changing the backend's global clear setting; the overlay pointer hit-test runs first and the pointer scope maps keep the scene/overlay separation. An overlay scene or camera is never created on its own from asset data; ownership stays with the application.

`Node.setLayout()` normalizes edge, offset, size and anchor values in finite/bounded form; layout traversal only runs on the scene graph provided by the application. During a resize, `ExiEngine` repeats the layout in the overlay viewport and does not change the transforms of the main gameplay scene on its own.

Focus traversal collects at most 4,096 candidates for visible nodes and keeps `tabIndex` in the `-1..32,767` range. `onKeyDown` is only sent to node/parent chains the application has explicitly made focusable; the event object is reused as a transient, and `preventDefault()` is only passed to the native keydown when the callback asks for it. A key callback exception stays within the engine's `runtime-error`/stop boundary.

`NineSliceSprite` produces at most nine fixed quads; border values are kept finite and within world limits, edges are compressed proportionally if the target size is small, and UV edges are pulled to the texture boundary if the texture frame size is exceeded. Resize calculations reuse bounded scratch areas; no user texture or shader is run, and the nine pieces are subject to the existing batch/culling and texture budgets.

## Rule for new features

`AssetLoader.loadMany()` keeps the same-origin, byte limit and `AbortSignal` rules; it only loads the allowed `texture`, `json`, `bytes` and `atlas` types and `ktx2` when an explicit decoder adapter is given. In an atlas entry, `url` (texture) and `atlasUrl` (JSON metadata) still go through the same `loadTexture()`/`loadJSON()` limits. The general response byte budget is 16 MiB by default with an absolute 64 MiB ceiling. A manifest is limited to 4,096 entries, asset keys to 256 characters and a single response stream to 16,384 parts; many small chunks cannot indirectly exceed the byte budget. `AudioManager.load()`/`loadMany()` also pass the `integrity` option to the existing `AssetLoader.loadBytes()` SHA-256 verification; audio decode/cache does not start until the hash passes. An audio batch is limited to 4,096 entries, 16 workers, audio key/URL validation, `AbortSignal` and the same decoded PCM/voice budgets. Audio buses only work with in-app `AudioBuffer`s and fixed Web Audio nodes; they run no remote scripts or shaders.
In addition to the 4 MiB default JSON byte budget, `AssetLoader.loadJSON()` enforces node and depth limits with a bounded text scan before `JSON.parse()`; the exact post-parse graph validation is also kept. The loader's image/texture/JSON/response limits are tied to the capacity allocated in the constructor; directly raising the public limit fields is rejected. Per-call `maxJSONBytes`, `maxJSONNodes` and `maxJSONDepth` are only clamped to the loader's narrower limit. A value that exceeds the limit is not returned and is not written to the loader cache. The core promises no streaming JSON parser; the byte and pre-parse token limits are the main defense.

The `AssetLoader` texture cache is limited to 256 textures and a 128 MiB pixel budget by default. The `loadTexture()`/`loadKTX2()`/`cacheTexture()`/`release()` inputs re-validate the entry and pixel totals after direct mutation of the public `cache` Map; the `maxCacheTextures`/`maxCachePixels` capacity also stays tied to the budget allocated in the constructor. When the budget is full, new texture results are not cached; no automatic eviction that silently destroys existing application references is done.

Asset integrity depends on the application's distribution manifest: the optional `integrity: "sha256-..."` for `loadBytes()`, `loadJSON()`, `loadTexture()` and `loadKTX2()` is verified with Web Crypto. Texture/KTX2 results with integrity are not written to the cache, so a wrong hash does not stay in the cache; `loadAtlas()` takes the texture and JSON metadata hashes separately as `integrity`/`atlasIntegrity`. Unsupported algorithms or malformed hash formats are rejected.

The WebGL2/WebGPU renderers enforce a total budget of 128 MiB and 4096 GPU texture resources by default; `maxTextureBytes` can be at most 512 MiB and `maxTextureCount` at most 4096. Normal texture and RenderTexture allocations are validated before they enter the budget; atlas `baseTexture` frames share the same GPU resource. The renderer's public texture and device-limit fields are tied to the constructor/device snapshot; direct enlargement is rejected with `EXI_RENDER_CONFIG`. A budget error is reported as a controlled input error with `EXI_TEXTURE_BUDGET` and is not counted as device/context loss.

`AssetLoader.destroy()` cancels pending fetch controllers and prevents late byte/bitmap results from being written into the destroyed engine cache; calls using different `AbortSignal`s for the same byte/texture load share a single bounded fetch/decode job, and a caller abort only rejects the related promise without cutting the shared underlying request. `clear()` deliberately only changes the cache generation. `AudioManager` also treats pending decode results as invalid after engine teardown or a single `unload()`; it does not share different integrity requests for the same name/URL and does not decode before verification passes, so an old or unverified audio buffer cannot be written back into the cache.

An abort inside `AudioManager.loadMany()` rejects running caller promises without making them wait; `load()` shares pending byte/decode work for the same key, the shared `AssetLoader` job is not cancelled by a caller signal, and only the related caller promise is rejected. The batch worker count is kept bounded. If decoding completes, the result is only written to the cache if the manager/key generation is still valid.

`inspectKTX2()` and `loadKTX2()` validate the KTX2 identifier, 2D/face/layer/depth, mip count, 64-bit level/metadata ranges, and pixel and uncompressed byte budgets before the decoder runs. The core only builds the uncompressed RGBA8 KTX2 path directly; a Basis/ETC1S/UASTC/Zstd decoder is never loaded on its own remotely or from inside an asset, and only a bounded decoder callback explicitly provided by the application is run.

`AudioManager` limits active Web Audio source nodes to 64 voices by default and 256 absolute; a single audio response has a 64 MiB ceiling and total decoded PCM a 512 MiB ceiling. `maxBytes`, `maxDecodedBytes` and `maxVoices` are tied to the constructor snapshot; direct enlargement is rejected with `EXI_AUDIO_CONFIG`. The `ended` callback releases the voice record; `stopVoice()`/`stopAll()` and `unload()` stop the related sources and clear their references. The voice limit is a second live-node/CPU cost limit, independent of the decoded PCM budget.

The pan value in `AudioManager.play()` and `setVoicePan()` is clamped to `-1..1`; `setVoiceVolume()` also keeps volume in `[0,1]`. The default center pan creates no extra `StereoPannerNode`; a panner is only added to the graph lazily for off-center values, and is disconnected and cleaned up when returning to center and when the voice stops. A browser without panner support returns a controlled error.

Audio bus mute state is kept separately: `setBusMuted()` temporarily pulls the gain node to 0, `setBusVolume()` updates the target volume of a muted bus, and unmute restores the real last value. `fadeBus()` uses native AudioParam automation, limits the duration to 60 seconds and cancels old schedules on new direct/mute/fade calls. This way mute/unmute and menu music transitions do not accumulate volume settings or unbounded automation events.

`AudioManager.suspend()`/`resume()` only control the existing AudioContext; they do not create a context to try to get around the autoplay policy. `ExiEngine.pauseAudio` is on by default and reopens a running context the engine itself stopped during visibility/manual resume; it does not take ownership of a context that was already suspended. The `pauseAudio: false` option leaves the audio lifecycle to the application.

A new loader or plugin is not taken into the core without a source allowlist, byte limit, parse validation, abort support and safe error behavior for bad content. Every non-trivial security path is protected by at least one runnable smoke test.

The Graphics and particle APIs only produce numeric geometry; they accept no shader or script text. The particle pool is limited by `maxParticles` and does not aim to allocate unbounded resources per frame.

The RuntimeAgent and MCP `inspect` only treat engine methods on the object prototype as callable. Game callbacks on the instance, such as `onUpdate`, `onRender` and `onStatus`, are not taken into the agent method list and cannot be run through `exi_call`/runtime `call`; gameplay callbacks only run from project files after human/agent review.

For APIs that take callbacks, the only exception is selecting a function the browser page registered in advance with `RuntimeAgent({ callbacks })` through a `{"$callback":"name"}` reference in JSON. MCP carries no callback bodies, closures or function source; there is no `eval`/`new Function`. The registry is limited to 256 callbacks and 256 characters per name, an unknown name returns a controlled error, and the callback result goes through the existing bounded RuntimeAgent serializer. This safe selection layer is not a sandbox; project files must still be kept within the trusted agent/review boundary.

### MCP optimistic file versions

`exi_file_read`/`exi_file_list` and `exi_asset_read`/`exi_asset_list` only return `{ bytes, mtimeMs }` version metadata. An agent can pass this value as `expectedVersion` to an `exi_file_write`, `exi_file_begin`, `exi_asset_write`, `exi_asset_begin` or `exi_project_apply` call; if the existing file has changed, the operation is rejected with `EXI_MCP_FILE_CONFLICT`. A chunk commit checks the target again and does not move a stale upload onto the target. This mechanism is an optimistic concurrency guard, not a filesystem lock; the external race window between the last check and the rename is explicitly accepted.

### Upload integrity guard

`expectedSha256` is an optional content integrity check; only a 64-hexadecimal SHA-256 digest is accepted. Direct text/asset writes compare the hash before the temporary-file rename, and chunk uploads compare the incremental hash before commit. On a mismatch `EXI_MCP_UPLOAD_INTEGRITY` is returned and the target file is not changed. This check does not turn MCP's trusted-local-process boundary into a sandbox.

## Custom filters (`registerFilter`)

`registerFilter(name, { glsl, wgsl })` is the single place where caller-supplied shader text reaches the GPU. It is designed for code that ships with the game, not for runtime or remote content:

- It is denied to AI agents: `isAgentCallableExport()` in `src/ai/public-methods.js` hides it from the MCP `exi_api` manifest and rejects it in `exi_function`, `exi_export_call` and the browser RuntimeAgent. Do not wire it to network, save-file or user-generated input.
- Only a function body is accepted, for both backends. Bodies are limited to 4 KiB, at most 16 filters exist, names are `^[a-z][a-z0-9-]{1,31}$` and cannot shadow built-ins.
- Bodies must keep braces balanced (they cannot close their function and declare top-level code), must `return`, and may not contain `#` directives, backslashes, `uniform`, `layout`, `precision`, WGSL attributes (`@`) or `enable`/`requires`/`diagnostic`.
- Compilation happens inside the engine's own programs; a body that fails to compile is disabled on that backend (status `error`) while everything else keeps rendering, and the previous working programs/pipelines are kept until a rebuild succeeds.
- GPU code runs in the browser's GPU sandbox; the remaining risk of a hostile body is performance (an expensive loop). Treat filter bodies like the rest of your shipped code: reviewed and versioned.
